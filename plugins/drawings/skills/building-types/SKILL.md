# Building types

Reads: programme, massing, drawing-graphics, panel-layout

Work in the proposal folder you are told, else the newest in the project's `proposals/`, else a new `proposals/<YYYY-MM-DD>_draft/`, and write only into `building-types/`. The inputs are the programme table (`programme/programme.csv`: use, area, plot, homes, residents, source), the new buildings of the massing (`massing/massing.geojson`: buildings with footprint, `floors`, `height_m`, `use`, `type`), the drawing standard (`drawing-graphics/style.json`) and the drawing's frame (`panel-layout/layout.json`). If the massing or the programme is missing, say so to the user and ask whether to wait for it; if they don't answer or say go on, the script draws a stand-in: generic types of assumed size, or the programme line taken from the massing. It writes STAND-IN in the drawing and in `summary.md`, so nobody takes it for the design. Never invent a number to fill a gap.

**Run it.** Copy `${CLAUDE_SKILL_DIR}/config.example.json` to `building-types/config.json` and fill each value from the brief's checklist with its page, or leave it empty. Then run `python "${CLAUDE_SKILL_DIR}/scripts/building_types.py" --proposal <proposal folder>`. It needs Python 3.11 or newer and nothing else to install; the PNG needs a headless Chrome, Chromium or Edge. The scale comes from this drawing's frame in `panel-layout/layout.json`, else from `config.json`, else 1:500, and the summary says which. Fix the script, never the drawing.

**What it draws.** One type per building `type` among the new buildings (or per `use` for community buildings), shown by its building of median footprint, turned so its longest side faces left. All types are drawn in one true isometric (30°, true lengths on all three axes) at one scale, standing on one baseline, from low to high. The buildings are white (the standard's `new`), their left faces in shade (towards its `shadow`), and the floors are fine lines. Under each type its name, the programme rows it answers with their pages, its footprint in m², floors and height in m, and its floor area with the number of buildings of that type. The scale bar stands upright on the baseline, because heights are true length in an isometric drawing. Colours, line weights and fonts come from `drawing-graphics/style.json`; without it, black on white with one accent. Large (1:200 to 1:500) the floor lines carry the drawing; small (1:1000 and smaller) the script drops floor lines that would print closer than 0.8 mm, and the types read as volumes. If the row is wider than its frame (or the panel width in `config.json`), the script wraps it into two or more rows of the same height, on a shared baseline grid, at the same scale, and says so in the summary; never change the scale yourself.

**Write and report.** The script writes `building-types_<scale>.svg` (scale as `1-500`, print size in mm) and `.png`, `types.csv` (one row per type with its figures and sources) and `summary.md` in three lines. Open the PNG once: types that float above the baseline, overlap, or have walls showing through roofs are mistakes. End by telling the user which files were written and where, and how the drawing looks: how many types, the tallest, the look's source, and every stand-in.
